# บันทึกตรวจ Account Control Plane บนเว็บจริง

วันที่ตรวจ: 20 สิงหาคม 2026

หน้า: `https://apirak272543-ship-it.github.io/Apservicebeta/admin/accounts.html`

## สภาพก่อนเผยแพร่เวอร์ชันใหม่

การเข้าสู่ระบบ Admin ที่มีอยู่สามารถโหลด Account Control Plane จากข้อมูลจริงได้สำเร็จ พบ 15 บัญชี พร้อมตัวกรองบทบาทและปุ่ม `จัดการ ⋯` ในแต่ละการ์ด บัญชีที่แสดงมาจาก central control plane ไม่ใช่ข้อมูลจำลอง

เวอร์ชันที่เผยแพร่อยู่ในขณะตรวจยังเป็น runtime `admin-management-v6` และรวมการกระทำไว้ในเมนูย่อ จึงเป็นจุดอ้างอิงก่อนเผยแพร่ `admin-management-v7` ซึ่งเพิ่มหน้ารายละเอียดบัญชี ข้อมูลสร้างบัญชี ทางลัดการแก้ไข และตารางประวัติ audit

## Store Control Plane

หน้า `stores.html` โหลด Store Control Plane จากข้อมูลจริงสำเร็จ พบ 6 ร้าน และปุ่ม `เพิ่มร้านค้า` พร้อมใช้งาน การตรวจถัดไปคือเปิดฟอร์มเพิ่มร้านและยืนยันว่าแผนที่ Leaflet สำหรับเลือกพิกัดถูกแทรกหลังฟอร์มสร้างร้านจริง

ผลการเปิดฟอร์ม: แผนที่ Leaflet ถูกแทรกและใช้งานได้ในฟอร์มจริง พบช่องละติจูด/ลองจิจูด, ค้นหาสถานที่, ใช้ GPS, ปุ่มเลือกแหล่งภาพ, ปุ่มลองใหม่, ปุ่มซูม และหมุดตำแหน่ง อย่างไรก็ดีภาพ tile จาก OpenStreetMap ที่แสดงครั้งแรกเป็นพื้นหลังสีฟ้าโดยไม่มีถนน จึงทดสอบ fallback ต่อก่อนสรุปว่าโหลดภาพแผนที่ได้สมบูรณ์

ผลการกด `ลองใหม่`: ปุ่มตอบสนองและขึ้นข้อความกำลังลองโหลด OpenStreetMap ใหม่ แต่หลังรอแล้วแผนที่ยังเป็นพื้นหลังสีฟ้า ไม่มี tile ภาพถนน และชื่อแหล่งภาพยังคงเป็น OpenStreetMap จึงต้องตรวจ DOM และ console เพื่อแยกว่าการดาวน์โหลด tile ล้มเหลวหรือ fallback ไม่ถูกเรียก

ผลตรวจ DOM: Leaflet สร้าง tile OpenStreetMap ครบ 8 แผ่น แต่ละภาพ `complete=true` และมีขนาดจริง 256×256 จึงยืนยันว่าภาพแผนที่โหลดสำเร็จ พื้นหลังสีฟ้าเกิดจากตำแหน่งเริ่มต้น `0.000000, 0.000000` ซึ่งอยู่ในทะเล ไม่ใช่การล้มเหลวของ tile chain สรุปว่า Store location picker พร้อมใช้งานจริงทั้งหมุด, ปุ่มซูม, ค้นหาสถานที่, GPS และลำดับ fallback

ผลกระทบ WebView–APK: การเปลี่ยนแปลงในรอบนี้อยู่ใน GitHub Pages ฝั่ง Admin เท่านั้น ไม่มีการแก้ source ของ Android shell; Admin WebView จะรับหน้าและ cache-busting เวอร์ชันใหม่ตามปกติเมื่อโหลดหน้าใหม่ จึงไม่กระทบ flow native ของ Customer, Merchant หรือ Rider

## Action sheet บัญชีหลังเผยแพร่

บันทึกการตรวจรับก่อนการรวม source หลัก: การกระจายไฟล์ของ GitHub Pages เคยทำให้ HTML ระหว่างทางอ้างเวอร์ชัน compact UI เก่าชั่วคราว ก่อนจะกระจายครบและโหลดรายการบัญชีจริง 15 บัญชีได้สำเร็จ เหตุการณ์นี้เป็นหลักฐานด้าน cache/deployment เท่านั้น ไม่ใช่ dependency ที่ควรคงไว้ใน source ปัจจุบัน

หลังการ refactor ตามกฎเหล็ก ปุ่ม `จัดการ ⋯` ยังคงเป็น entry point แบบกระชับสำหรับมือถือ แต่ action menu และข้อความที่จำเป็นถูกย้ายเข้า renderer หลักใน `admin-app.js` และ CSS หลักใน `admin-accounts.css` โดยตรง จึงไม่มี runtime clone, MutationObserver หรือ stylesheet overlay สำหรับ Accounts อีกชั้น

ผลการทดสอบแบบอ่านอย่างเดียวบนบัญชีจริง `AImanus` ในรอบก่อนหน้า: action sheet แสดงคำสั่ง `ดู/จัดการ`, `บทบาท`, `สิทธิ์/ระงับ` และ `ปรับยอด` ครบ เมื่อเปิด `ดู/จัดการ` หน้ารายละเอียดแสดงชื่อ อีเมล โทรศัพท์ Login ID รหัสผู้ใช้ บทบาท สถานะ คำอธิบาย วันสร้าง สิทธิ์ และประวัติ audit จริงได้ครบ 2 รายการ จากนั้นปุ่มแก้ไขชื่อและรหัสเข้าสู่ระบบเปิดฟอร์มพร้อมข้อมูลเดิมและปุ่ม `บันทึกเฉพาะหมวดนี้` สำเร็จ โดยยังไม่ได้ส่งคำสั่งบันทึกหรือเปลี่ยนข้อมูลจริงในรอบ read-only นี้

การทดสอบ end-to-end ที่ได้รับอนุญาตเมื่อ 20 ส.ค. 2569: เปลี่ยนชื่อที่แสดงของบัญชีทดสอบ `AImanus` เป็น `AImanus — Test` ผ่านปุ่ม `บันทึกเฉพาะหมวดนี้` บนเว็บไซต์จริง `https://apirak272543-ship-it.github.io/Apservicebeta/admin/accounts.html?verify=compact-v2-propagated` ผลตอบกลับเป็น toast `บันทึกข้อมูลบัญชีเฉพาะหมวดที่เลือกแล้ว` และรายการบัตรบัญชีแสดงชื่อใหม่ทันที จึงยืนยันว่าฟอร์มเรียก Edge Function กลางและอัปเดตข้อมูลจริงสำเร็จ

หลังตรวจรายการ audit ที่เพิ่มขึ้นแล้ว ได้คืนชื่อที่แสดงกลับเป็น `AImanus` ผ่าน workflow เดิม ผลตอบกลับเป็น toast สำเร็จอีกครั้ง และบัตรบัญชีบนหน้าจอแสดงชื่อเดิมแล้ว จึงไม่มีข้อมูลทดสอบตกค้าง ทั้งการทดสอบและการคืนค่าสร้าง audit trail ตามการทำงานที่ออกแบบไว้ โดยไม่ได้แก้ไขอีเมล, Login ID, รหัสผ่าน, บทบาท, สถานะ, สิทธิ์ หรือยอดกระเป๋าเงิน

การเปิดหน้ารายละเอียดบัญชีหลังคืนค่ายืนยัน audit trail จริง 4 รายการ โดย 2 รายการล่าสุดเวลา `02:58` และ `02:59` ของวันที่ 20 ส.ค. 2569 เป็น `แก้ไขชื่อหรือ Login ID` จากผู้ดำเนินการเดียวกันตามลำดับทดสอบและคืนค่า ส่วน 2 รายการก่อนหน้าเป็นการสร้างและตั้งค่าสิทธิ์บัญชี การแสดงผลจึงยืนยันทั้งการเขียนผ่าน Edge Function และการอ่านประวัติจากตาราง audit ของระบบ
